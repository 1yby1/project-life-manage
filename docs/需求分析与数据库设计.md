## 一、项目概述

面向 To-B 销售/项目交付场景的 CRM + 项目全生命周期管理系统,覆盖 **线索 → 商机 → 合同 → 项目交付** 的完整漏斗。

**技术栈**: Spring Boot 3.5.3 + MyBatis Plus + MySQL 8 + JWT + Vue 3 + Element Plus + Vite

**核心约束**(文档原文):
- 所有团队均需开发 **登录功能** 和 **角色管理**
- 未登录或越权访问 → 退回登录页
- 团队可 **任选一个功能模块** 作为大作业交付

## 二、功能模块

### 模块 1:客户管理

| 子功能 | 负责角色 | 要点 |
|---|---|---|
| 客户列表录入 | 商机管理员 | 客户名称、地市、法人必填;地址、注册地址、注册机构选填 |
| 派单 | 商机管理员 | 派给客户经理走访 |
| 客户接触 | 客户经理 | 查看分配给自己的待走访清单 |
| 走访录入/完成 | 客户经理 | **完成走访后不可再修改** |
| 客户信息完善 | 客户经理 | 补全地市、地址、信用编码、行业、联系人等,可多次保存 |

### 模块 2:合同管理

| 子功能 | 要点 |
|---|---|
| 合同首页 | 一级 + 二级菜单;左列执行中 / 右列已完成;"今年/去年/2019年" 同时作为标签与筛选条件 |
| 合同列表 | 功能同首页;执行中可"关闭合同";已交付不显示关闭按钮;合同正文可新页面预览/下载;付款节点弹框展示 |
| 新增合同 | 下拉框可写死;客户从客户模块取;必填项校验;合同金额 = 付款节点总额;合同名不可重复 |
| 周报管理 | 销售每周向主管提交周报(出勤 + 本周 + 下周);主管可点评 |
| 专题分析 | 在途合同(区总用,催流程催签约)、已验收项目(PMO 月度汇报,含金额/时间/客户/BU);支持条件检索 |

### 模块 3:线索管理

| 子功能 | 负责角色 | 要点 |
|---|---|---|
| 线索清单 | 所有人 | 默认不展示"已转商机";BU 可筛选;表头有"我参与的"等分类统计 |
| 线索录入 | 所有人 | 进入 `ENTRY` 状态 |
| 线索收集 | 收集人 | "保存"临时保存可反复;"确认"完成收集进入分发 |
| 线索分发 | 分发人 | 指派客户经理 |
| 线索培育 | 客户经理 | 完善详情、签约概率等 |
| 转商机 | 客户经理 | 培育完成后进入商机阶段 |

### 模块 4:商机管理

| 子功能 | 要点 |
|---|---|
| 商机列表 | 显示商机基本信息与阶段 |
| 推进模板 | 必含 4 环节:验证机会点、谈判与合同签订、项目实施、验收与交付;仅提供选择,不可编辑 |
| 环节责任人 | 可逐环节指定;未指定则由"铁三角"(PM/SM/DM)操作;允许项目详情中重新指定 |
| 组员管理 | 核心组仅项目经理可操作;支撑组可由 PM / CM / DM / SM 管理;按角色分组展示 |
| 项目运作 | 按模板生成环节视图和关键任务;默认责任人 = 项目经理 |
| 任务指派 | 关键任务自动生成,由 SM/CM/DM/商机负责人编辑指派 |
| 任务回复 | 关闭前可多次回复与修改 |

### 2.5 模块间关系总览(为何四模块并存且不冲突)

需求文档原文允许「任选一个模块」,本系统**四个模块全部实现**,通过下面的耦合/松耦合策略确保它们既独立可降级、又能串联成完整漏斗。

**漏斗主线**(横向时序):

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 客户管理 │ → │ 线索管理 │ → │ 商机管理 │ → │ 合同管理 │
└──────────┘   └──────────┘   └──────────┘   └──────────┘
   主数据         机会发现        机会运作        交付收尾
   "谁"           "可能买什么"    "怎么卖"        "卖成什么样"
```

**两条耦合纽带**:

1. **纵向(主数据共享)** — 所有业务表通过 `customer_id` 挂回 `crm_customer`,客户是全局主数据;
2. **横向(漏斗串联)** — `crm_opportunity.lead_id` + `crm_contract.opp_id` 形成单向反查链:合同 → 商机 → 线索 → 客户。

**自动衔接钩子**(把模块焊成一体的关键):

| 触发动作 | 来源模块 | 副作用 | 规则 |
|---|---|---|---|
| 线索 `convert` | 线索 | **自动**创建商机占位(`lead_id` 反查源头) | #16 |
| 商机选模板 | 商机 | 自动展开 4 条 `crm_opp_stage` 实例 | #17 |
| 标记付款已付 / 标记验收 | 合同 | 触发 `tryAutoComplete` 三条件检查 | #24 |

**松耦合边界**(每个模块都可单独演示):

- 客户管理不依赖任何其他模块即可运行;
- 商机可从客户直接新建,不强制来自线索;
- 合同 `opp_id` 可空,支持"飞单"(不挂商机直接建合同);
- 周报模块完全独立,通过 `sys_user.supervisor_id` 与组织挂钩,服务全漏斗的运营观察。

**角色分工无冲突** — 四个模块的写操作由不同角色组合承担(详见第四节权限矩阵),同一用户可持多角色实现跨模块串联,但同一动作只属于一个模块。

> 完整 ER 与跨模块时序见 [第七节](#七er-关系图) 与 [第十节](#十模块协作时序)。

## 三、角色体系

采用 **双层角色** 设计:

### A. 系统大角色(sys_role)

每个用户分配一到多个系统角色,决定能进入哪些功能菜单。**多角色挂在 `sys_user_role` 关系表上;后端 Spring Security 把每个角色封装为 `SimpleGrantedAuthority("ROLE_" + role_code)`,用 `hasRole('XXX')` / `hasAnyRole(...)` 判断**。

| 编码 | 中文 | 职责 |
|---|---|---|
| `ADMIN` | 系统管理员 | 用户管理、角色管理、模板管理 |
| `OPP_ADMIN` | 商机管理员 | 录入客户、派单、整体调度 |
| `CUSTOMER_MANAGER` | 客户经理 | 走访客户、完善信息、线索培育 |
| `SALES` | 销售人员 | 提交周报、录入线索 |
| `SUPERVISOR` | 主管 | 点评下属周报 |
| `SOLUTION_MANAGER` | 解决方案经理 | 商机方案制定(铁三角) |
| `DELIVERY_MANAGER` | 交付经理 | 项目交付(铁三角) |
| `PROJECT_MANAGER` | 项目经理 | 项目运作(铁三角核心) |
| `REGION_HEAD` | 区总 | 在途合同专题 |
| `PMO` | 项目管理部 | 已验收项目专题、月度汇报 |
| `USER` | 普通用户 | 录入线索(所有人兜底) |

### B. 业务角色(挂在具体业务单据上)

同一个人在不同单据上可承担不同业务角色,动态变化。

| 业务角色 | 存放位置 |
|---|---|
| 线索录入人 | `crm_lead.entry_by` |
| 线索收集人 | `crm_lead.collector_by` |
| 线索分发人 | `crm_lead.distributor_by` |
| 客户经理(线索/商机) | `crm_lead.manager_id` / `crm_opportunity.manager_id` |
| 项目经理 | `crm_opportunity.pm_id` |
| 解决方案经理 | `crm_opportunity.sm_id` |
| 交付经理 | `crm_opportunity.dm_id` |
| 环节负责人 | `crm_opp_stage.owner_id` |
| 任务受理人 | `crm_opp_task.assignee_id` |

## 六、状态机

### 6.1 线索 (`crm_lead.status`)

```
ENTRY ──[收集人点确认]──> COLLECTED
      [收集人]               [分发人指派]
                            ↓
                          DISTRIBUTED
                            [客户经理接收]
                            ↓
                          NURTURING ──[转商机]──> CONVERTED
```

### 6.2 商机 (`crm_opportunity.stage`)

```
VALIDATE ──> NEGOTIATE ──> IMPLEMENT ──> DELIVERY
 验证机会点    谈判签订     项目实施      验收交付
```

### 6.3 合同 (`crm_contract.status`)

```
EXECUTING ──┬─[自然完成]──> COMPLETED
            │
            └─[商机管理员关闭]──> CLOSED
```

> ⚠️ **COMPLETED 的合同不可关闭**,前端不显示"关闭合同"按钮。

### 6.4 客户走访 (`crm_customer_visit.status`)

```
PENDING ──> DOING ──> COMPLETED (不可逆!)
 待走访     走访中      已完成
```

> ⚠️ 一旦 `COMPLETED`,任何走访记录更新都需 Service 层拒绝。

### 6.5 任务 (`crm_opp_task.status`)

```
TODO ──> DOING ──> DONE (close_time 写入后不可改)
```

### 6.6 周报 (`crm_weekly_report.status`)

```
DRAFT ──[销售提交]──> SUBMITTED ──[主管点评]──> COMMENTED
```

## 八、关键业务规则

Service 层实现时必须遵守:

1. **越权拦截** — 未登录 → 重定向 `/login`;已登录但无权限 → 403,前端跳回登录页
2. **走访不可逆** — `CrmCustomerVisit.status = COMPLETED` 时,所有更新接口直接拒绝
3. **合同已交付不可关闭** — `status = COMPLETED` 时,`closeContract()` 接口返回错误
4. **合同名唯一** — `INSERT` 前校验 `contract_name` 不重复(DB 层已加 UNIQUE 约束兜底)
5. **合同金额一致** — `total_amount = SUM(crm_contract_payment.plan_amount)`,保存时校验
6. **线索默认隐藏已转商机** — 清单查询默认 `status <> 'CONVERTED'`,需参数 `includeConverted=true` 才显示
7. **核心组保护** — `crm_opp_team.member_type = 'CORE'` 的增删改仅 `crm_opportunity.pm_id = 当前用户` 可操作
8. **铁三角缺省** — 商机环节(`crm_opp_stage`)未指定 `owner_id` 时,只有 PM/SM/DM 三人可操作该环节任务
9. **任务关闭后不可改** — `crm_opp_task.close_time` 非空时,所有更新接口直接拒绝
10. **周报唯一** — `(user_id, year, week_num)` 唯一,同一人同一周只有一份
11. **多角色一致性** — 登录响应(`/auth/login`) 与 `/auth/me` 均返回 `roles: string[]`(角色 code 数组);前端按数组判断,不再依赖 `roleId` 单值。后端 `CustomUserDetails.authorities` 来源于 `sys_user_role`,所有用户至少持有 `USER` 角色(兜底)。
12. **派单唯一性** — 同一 `customer_id` 在 `crm_customer_visit` 中至多一条记录(任何 `status` 都阻断重派);Service 层 `CustomerVisitServiceImpl.dispatch()` 在插入前调用 `findActiveByCustomerId()` 校验。本轮不支持"撤销派单/重派"。
13. **走访归属** — `crm_customer_visit` 的写操作(`saveRecord` / `complete`)只能由 `manager_id == 当前用户` 的 CUSTOMER_MANAGER 执行;OPP_ADMIN 不能改走访记录。Service 层 `ensureOwner()` 强制校验。
14. **商机模板一次性应用** — `applyTemplate` 仅当 `crm_opp_task` 在该商机下无任何记录时才允许,否则报错"已生成任务,不可重新选模板";应用时按 `template_id` 删除旧 stages → 按 `crm_opp_template_stage` 顺序重建。owner_id 留空,缺省由铁三角操作。
15. **铁三角任务派发(简化版)** — 关键任务的创建/更新/关闭权限放宽到商机的 `pm_id` / `sm_id` / `dm_id` / `manager_id` 任意一人(本轮 MVP);需求文档"分配关键任务由 SM/CM/DM 在自己环节下"的精细约束推迟实现。任务回复对受理人 + 铁三角开放。任务关闭后(`close_time != null`)所有写操作直接拒绝(规则 #9 强约束)。
14. **线索状态机简化** — 实现为 4 态(`ENTRY` → `COLLECTED` → `DISTRIBUTED` → `CONVERTED`),不引入 `NURTURING` 中间态。`DISTRIBUTED` 阶段即"已派给客户经理可培育",可多次保存培育详情;转商机前必须先培育(`progress_desc` 非空且含 `opportunityOwnerId`)。
15. **线索培育详情存 JSON** — `crm_lead.progress_desc` (TEXT) 存培育表单 7 字段(`projectName`/`expectedPurchaseTime`/`predictedAmount`/`clueLevel`/`solutionManager`/`opportunityOwnerId`/`keyContact{}`)的 JSON 序列化。`win_rate` 列单独存(0-100,前端 0-1 *100)。
16. **录入人即收集人 + 转商机创占位** — `POST /leads/:id/collect` 校验 `entry_by == 当前用户`,同时把 `collector_by` 也填本人;`POST /leads/:id/convert` 创建一条 `crm_opportunity` 占位记录(opp_name = "{客户名}-{线索标题}-商机", manager_id/pm_id = 培育时的 opportunityOwnerId, stage = VALIDATE),不展开 `crm_opp_stage` 环节实例。
17. **合同金额校验** — `crm_contract.total_amount` 必须**严格等于** `SUM(crm_contract_payment.plan_amount)`;Service 层 `ContractServiceImpl.create()` 入库前 `BigDecimal.compareTo` 校验,不允许误差。合同名 `contract_name` 全局唯一(DB UNIQUE + Service 提前查询给友好错误)。
18. **合同状态机不可逆** — `EXECUTING → COMPLETED`(自然交付,本轮未实现自动触发,留作后续) 或 `EXECUTING → CLOSED`(OPP_ADMIN 主动关闭,Service 层 `close()`);**`COMPLETED` 状态不可关闭**(规则 #3 实现:返回 400 "已交付合同不可关闭");`CLOSED` 不可重复关闭。前端 `ContractListView` 仅在 `EXECUTING` 状态显示「关闭」按钮。
19. **周报状态机锁定** — `DRAFT` 可反复保存(`(user_id, year, week_num)` 唯一,update by id);`SUBMITTED` / `COMMENTED` 状态下 `saveDraft()` 拒绝,只允许查看。提交前后端读 `sys_user.supervisor_id` 自动绑定 `crm_weekly_report.supervisor_id`,无主管的用户不能提交周报。
20. **周报点评归属** — `POST /weekly-reports/:id/comment` 仅当 `crm_weekly_report.supervisor_id == 当前用户` 时允许;不限制点评次数,但首次点评会把 `report.status` 从 `SUBMITTED` 推进到 `COMMENTED`(后续点评保持 `COMMENTED`)。员工 `DRAFT` 状态不可被点评。
21. **商机阶段推进顺序不可逆** — `POST /opportunities/:id/advance-stage` 仅商机的 `pm_id` 可调;按 `VALIDATE → NEGOTIATE → IMPLEMENT → DELIVERY` 顺序推进,不可跳跃/倒退;`DELIVERY` 不可再推进(返回 400)。本轮**不**校验任务/环节完成度(用户决策:手动推进)。
22. **组员防重 + CORE/SUPPORT 权限边界** — `(opp_id, user_id)` 在 `crm_opp_team` 中唯一(insert 前校验);`CORE` 增删仅 `opp.pm_id == 当前用户` 可操作(业务规则 #7 严格落地);`SUPPORT` 增删需当前用户为商机的"铁三角"(PM/SM/DM/manager);CUSTOMER_MANAGER 暂不参与组员管理(因商机体系内 CM 不是本机人员)。
23. **任务进度独立 INT 列** — `crm_opp_task.progress` 为 0-100 INT NOT NULL DEFAULT 0;`PUT /opp-tasks/:id/progress` 仅受理人(`assignee_id`) 或铁三角可调,任务关闭(`status = DONE`)后拒绝;progress > 0 时自动从 `TODO` 推进到 `DOING`(避免"进度 80% 但仍是 TODO"的违和状态);关闭任务时强制 `progress = 100`。前端 `OpportunityDetailView` 的"调进度"按钮以滑块形式呈现(0/25/50/75/100 标记)。
24. **合同自然完成(双条件)** — 合同推进到 `COMPLETED` 必须**同时**满足:`status == EXECUTING` + 全部 `crm_contract_payment.status = 1` + `delivery_time != null`。Service 层 `ContractServiceImpl.tryAutoComplete()` 是幂等钩子,在 `setDelivery()` 与 `ContractPaymentServiceImpl.markPaid()` 两处调用,顺序无关。仅 `OPP_ADMIN` 可标记验收(`PUT /contracts/:id/delivery`,仅 EXECUTING)。`COMPLETED` 后再调 markPaid/setDelivery 无副作用(状态不动)。规则 #18(合同状态机不可逆)与 #3(已交付不可关闭)继续生效。

### 跨模块规则(8.X)

> 以下规则不属于单一模块,是把四个模块焊接成一个整体的"接缝合同"。

25. **漏斗衔接强约束** — 线索 `convert` 必须**原子地**做两件事:推进 `crm_lead.status = CONVERTED` + 在 `crm_opportunity` 插入占位记录(`lead_id` 字段非空且指向源线索)。任何一步失败需整体回滚,禁止"线索已转、商机未建"的中间态。Service 层 `LeadServiceImpl.convert()` 与 `OpportunityServiceImpl.createPlaceholderFromLead()` 在同一事务内执行。

26. **可降级容许** — 漏斗的横向链可断开:`crm_lead.customer_id` 允许为空(线索录入时还未确认客户),`crm_opportunity.lead_id` 允许为空(商机可不来自线索),`crm_contract.opp_id` 允许为空(支持"飞单"——不挂商机直接建合同)。**但** `crm_opportunity.customer_id` / `crm_contract.customer_id` 必须非空(主数据守恒)。这条规则保证四模块各自可单独运行,不强制使用者一定走完整漏斗。

27. **主数据守恒** — 删除 `crm_customer` 时若名下尚有 `crm_lead` / `crm_opportunity` / `crm_contract` 任一引用,Service 层应拒绝删除(本轮 schema 未启用 FK CASCADE,通过 Service 层校验落地)。客户的 `update_time` 任何字段写动作都需刷新,作为跨模块审计基线。本轮"删除客户"接口未实装,留作后续迭代。

## 十、模块协作时序

四个模块通过下面的时序串成端到端漏斗,每一步都标出**触发模块**和**对其他模块的副作用**,使"四模块如何协作"在文档级别可见。

### 10.1 端到端漏斗时序(13 步)

```
┌────────────┬───────────────┬──────────────────────────┬──────────────────────────────┐
│ 步 │ 角色      │ 操作                       │ 模块 / 跨模块副作用             │
├────────────┼───────────────┼──────────────────────────┼──────────────────────────────┤
│ 1  │ OPP_ADMIN     │ 新建客户 + 派单             │ 客户 → 写 crm_customer / visit │
│ 2  │ CUSTOMER_MGR  │ 走访(暂存→完成)+ 完善      │ 客户 (status: PENDING→DOING→COMPLETED)│
│ 3  │ SALES         │ 录入线索                    │ 线索 → 写 crm_lead (ENTRY)      │
│ 3a │ SALES         │ 自己确认收集                │ 线索 (ENTRY→COLLECTED)         │
│ 4  │ OPP_ADMIN     │ 分发到 CUSTOMER_MGR         │ 线索 (COLLECTED→DISTRIBUTED)   │
│ 5  │ CUSTOMER_MGR  │ 培育 + 转商机               │ 线索→商机 跨模块!              │
│    │               │                            │ (CONVERTED + 创建商机占位)     │
│ 6  │ PM            │ 选商机模板                  │ 商机 → 展开 4 条 crm_opp_stage │
│ 7  │ PM/SM/DM      │ 创建关键任务并指派          │ 商机 → 写 crm_opp_task         │
│ 8  │ PM            │ 推进商机阶段                │ 商机 (VALIDATE→NEGOTIATE→...) │
│ 9  │ OPP_ADMIN     │ 创建合同(关联客户+商机)    │ 合同 ← opp_id (跨模块反查)     │
│ 10 │ OPP_ADMIN     │ 标记付款已付 + 标记验收     │ 合同 → tryAutoComplete         │
│    │               │                            │ (满足三条件 → COMPLETED)      │
│ 11 │ PMO           │ 已验收专题查看              │ 跨模块聚合(合同+客户+BU)      │
│ 12 │ REGION_HEAD   │ 在途合同专题查看            │ 跨模块聚合(合同 EXECUTING)    │
│ 13 │ SALES/SUP     │ 提交周报 / 点评 / dashboard │ 周报独立 + 组织(supervisor)   │
└────────────┴───────────────┴──────────────────────────┴──────────────────────────────┘
```

### 10.2 跨模块自动副作用清单

| 触发点 | 来源模块 | 影响模块 | 实现位置 | 关联规则 |
|---|---|---|---|---|
| 线索 `convert` | 线索 | 商机(创建占位) | `LeadServiceImpl.convert` + `OpportunityServiceImpl.createPlaceholderFromLead`(同一事务) | #16 / #25 |
| 选商机模板 | 商机 | 商机内部(展开 stages) | `OpportunityServiceImpl.applyTemplate` | #17 |
| 商机推进阶段 | 商机 | 仅状态变更,本轮不外溢到合同 | `OpportunityServiceImpl.advanceStage` | #21 |
| 标记付款已付 | 合同 | 触发自动完成检查 | `ContractPaymentServiceImpl.markPaid` → `tryAutoComplete` | #24 |
| 标记验收时间 | 合同 | 触发自动完成检查 | `ContractServiceImpl.setDelivery` → `tryAutoComplete` | #24 |
| 三条件同满足 | 合同 | EXECUTING → COMPLETED | `ContractServiceImpl.tryAutoComplete`(幂等钩子) | #24 |
| 提交周报 | 周报 | 自动绑定 supervisor_id | `WeeklyReportServiceImpl.submit` | #19 |

### 10.3 数据反查链(可观测性)

任意一条合同向上追溯都能回到客户主数据:

```
crm_contract(id)
   ├─ customer_id ─→ crm_customer (主数据)
   └─ opp_id      ─→ crm_opportunity
                       ├─ customer_id ─→ crm_customer (一致性校验点)
                       ├─ lead_id     ─→ crm_lead
                       │                    └─ customer_id ─→ crm_customer
                       ├─ pm_id/sm_id/dm_id ─→ sys_user (铁三角)
                       └─ template_id ─→ crm_opp_template
```

> **一致性校验点**:同一条合同从 `customer_id`(直接)与 `opp_id.customer_id`(间接)拿到的客户应该相同。Service 层未做硬校验,留作后续审计点。

### 10.4 模块独立运行边界

| 入口场景 | 起步模块 | 是否需要前置数据 |
|---|---|---|
| 标准漏斗 | 客户 → 线索 → 商机 → 合同 | 完整链 |
| 跳过线索 | 客户 → 商机(直接新建)→ 合同 | 客户 |
| 飞单 | 客户 → 合同(opp_id 留空) | 客户 |
| 仅线索阶段 | 客户 → 线索(培育中,不转商机) | 客户 |
| 周报 | 销售 → 提交;主管 → 点评 | 仅组织(无业务数据依赖) |
